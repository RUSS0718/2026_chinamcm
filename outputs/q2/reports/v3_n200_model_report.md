## 1. 本轮回答的问题

协作协议将 n100 定义为开发和粗筛规模，将 n200 定义为冻结候选、预算和种子后的正式选型规模。本轮因此回答以下问题：

1. 独立参考基线 P0 与主干模型 P1、创新增强 P2 在真实 n200 上能否稳定生成合法且审计一致的布局；
2. 在相同的 `180 s / 30000 evaluations / 4 restarts` 上限下，P1/P2 是否降低 HPWL；
3. P2 的网络超图感知初始化是否相对 P1 形成稳定、足以改变选型的收益；
4. 当前结果是否具备可追溯到命令、配置、数据和布局的正式运行证据。

本轮不回答全局最优性，不把 timeout 解释为失败或最优性证明，也不使用 n200 反复调参。n300 仍是后续留出验证规模。

## 2. 固定问题定义与候选

固定轮廓仍采用 Q2 V1/V2 口径。设模块总面积为 `A_B`、死区比例为 `d=0.15`，正方形轮廓边长为

```text
L = sqrt(A_B * (1 + d))
```

模块允许 `0/90` 度旋转；边界接触合法，正面积重叠非法。模块引脚取旋转后矩形中心，Terminal 使用 `.pl` 中绝对坐标，目标为最小化所有网络的 HPWL。

| 配置 | 实际候选 | SA/约束 | 超图初始化 | 本轮角色 |
|---|---|---|---:|---|
| P0 | `Q2-SP` | classic SA，adaptive OFF | OFF | 独立参考基线，不是 ground truth |
| P1 | `Q2-BT` | Fast-SA，adaptive ON | OFF | 可靠共享主干与默认回退方案 |
| P2 | `Q2-HG` | Fast-SA，adaptive ON | ON | P1 上的网络感知创新增强 |

三组均使用合法 `shelf` 初始化。P1 与 P2 的核心差异是网络超图感知初始化开关，P2 是否被采用必须由 n200 结果而不是模型名称决定。

## 7. 候选总体结果

HPWL 越低越好。IQR 和 p90 用于观察波动与较差尾部表现。

| 配置 | 最好 HPWL | median HPWL | IQR | p90 | 最差 HPWL | 中位 evaluations | 中位 runtime/s |
|---|---:|---:|---:|---:|---:|---:|---:|
| P0 | 536183.5 | 543792.0 | 4703.625 | 549110.65 | 553106.5 | 7860.5 | 180.0084 |
| P1 | **487309.5** | **504410.5** | 12094.5 | 518658.05 | 521899.0 | 24731.5 | 180.0040 |
| P2 | 495154.5 | 505079.0 | **7409.125** | **512890.60** | **515909.5** | 24809.5 | 180.0032 |

相对 P0 的 median HPWL 改善为：

- P1：降低 `7.2420%`；
- P2：降低 `7.1191%`。

因此 P1/P2 均在相同 n200 时间预算下明显优于独立 P0 基线。P0 只能作为可信参考，不能写成全局最优或 ground truth。

P1 与 P2 的 median 仅相差 `668.5`，P2 比 P1 高 `0.1325%`；但 P2 的 IQR 比 P1 低 `38.7397%`，p90 比 P1 低 `1.1120%`。这说明 P1 的中心位置略优，而 P2 的波动和较差尾部更好，不能仅凭单个 best 或单个 median 声称某一方案全面占优。

## 9. Checkpoint 与同预算效率

| 配置 | 25% checkpoint | 50% checkpoint | 75% checkpoint | 100% checkpoint | 完整记录数（25/50/75/100） |
|---|---:|---:|---:|---:|---|
| P0 | 547508.75 | — | — | — | 20 / 0 / 0 / 0 |
| P1 | 517748.50 | 510131.25 | 504410.50 | — | 20 / 20 / 20 / 0 |
| P2 | 511880.00 | 507432.25 | 505079.00 | — | 20 / 20 / 20 / 0 |

P2 在 25% checkpoint 比 P1 低约 `1.1335%`，在 50% checkpoint 低约 `0.5291%`；到 75% checkpoint，P1 反而低约 `0.1325%`。预注册规则要求至少三个固定 checkpoint 达到 1% 改善，当前不满足，因此 `checkpoint_better=false`。

所有候选均未达到 100%（30000 evaluations），P0 甚至未达到 50%。这说明 P0 单次评价路径显著更慢，也说明本文不得写成“完整评价预算下 P1 已收敛优于 P2”。若人工复核认为 100% checkpoint 是必要门槛，必须另建新 attempt/版本重新注册预算，不能覆盖本批记录。

## 10. 机械选型与直接结论

预注册硬门槛要求每个候选 legal rate ≥ 0.90、20 条审计一致且无缺失。本轮三个候选均通过硬门槛。

机械选型按 median HPWL 升序排名：

1. P1：504410.5；
2. P2：505079.0；
3. P0：543792.0。

因此当前机械字段为 `selected=P1`。推荐把 P1 作为 Q2 当前主方案，原因是其预注册主指标排名第一，且模型结构比 P2 更简单。

`p2_same_budget=supports_p2` 不表示 P2 胜出。该字段成立是因为：

- P2 与 P1 的合法率均为 1.0；
- P2 median HPWL 仅比 P1 高 0.1325%，仍位于 1% 非劣范围；
- 两者中位首次合法评价均为 1，因此 P2 的首次可行性不慢于 P1。

同时，`better_hpwl=false`、`checkpoint_better=false`，配对胜负为 10:10。综合解释应为：P2 的超图初始化具有尾部稳定性价值，但尚无稳定收益足以替换 P1。P2 应保留为创新模块、消融结果和备选方案，而不是写成已证明优于 P1。
